Polymath implementation specification · v1.1

Documentation overview

This site summarizes the Polymath specification package for reading in a browser. The authoritative sources remain the Markdown files under docs/ and the machine-readable backlog. Implementation agents should use those sources directly. Pages may be opened locally without a web server.

Summary

  • Polymath is a mobile-first progressive web application for adaptive practice: spaced retrieval (FSRS), a skill graph, execution-based grading, an attempt-first tutor, and bench projects verified by evidence.
  • The stated learning outcome is working knowledge (tier L1) in each subject on the curriculum map, beginning with math, electronics, and embedded software.
  • Delivery follows a lean slice first (approximately 233 founder-hours of build effort), then deferred groups D1–D9; the capability spine documents long-term tracks (dual-use literacy, defense context, AI, cyber, physical builds) after the first walk.
  • Product copy is limited to evidence-backed claims; neuroscience, neurostimulation, and “top percentile” positioning are out of scope.

Recommended sequence for the founder

Phase −1

Four-week pre-build validation: spaced practice with Anki, generated problem sheets, and a study log. See Delivery plan.

Lean slice

Implement daily study with graph, FSRS, session builder, numeric and symbolic grading, PWA shell, and verified templates. Tutor and sandbox are deferred.

Go / no-go

Scorecard review four weeks after first production use. Extend the product by one deferred group at a time, selected from logged operational pain.
