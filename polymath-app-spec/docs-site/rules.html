Shared contract

Contract and product policy

The shared contract defines stack choices, identifiers, enums, core behaviours, and the claims policy for the entire package. Rulings in the change-decisions document take precedence when text conflicts.

Specification: docs/00-contract.md, docs/00a-change-decisions.md

Summary

  • Initial deployment targets a single founder learner; a small beta cohort follows later milestones.
  • Version 1 ships as a mobile-first PWA, not native iOS or Android applications.
  • Runtime must not serve learning items unless database status is verified.
  • Large language models may explain, tutor, and assist rubrics; they must not be the sole grader for numeric correctness or executable test outcomes.
  • Learner-submitted code and netlists execute only in an isolated sandbox without credentials or network access.
  • Approved positioning: adaptive practice with spaced retrieval, graded feedback, and guided builds.

Technology stack

Application

Next.js (App Router), React, Tailwind CSS, shadcn/ui, KaTeX, PWA manifest and service worker.

Platform services

Supabase: email magic-link authentication, PostgreSQL with row-level security, object storage.

Worker tier

Python 3.12 on Fly.io: symbolic grading, job processing, orchestration of sandbox runs.

Content

YAML in Git, verification pipeline, content:sync into PostgreSQL.

Controlled vocabulary

L0 through L3; tier L1 denotes working knowledge.
Session types
micro (≤20 min), focus (45–120 min), lab (120–240 min).
Device context
phone, desktop, bench.
Mastery states
unseen, learning, reviewing, mastered, decayed.
Skill identifier
{node}.{module}.{slug}, for example elec.dc.voltage-divider.

Normative product behaviours

  1. Each task requires an active learner response; passive consumption is not a valid completion path.
  2. Tutor and hint affordances unlock only after a recorded attempt; checkpoint sessions exclude the tutor.
  3. Strict-unaided assessment (no hints, tutor closed) is the primary integrity measure for retention claims.
  4. Offline attempts on cached numeric or multiple-choice items receive provisional grades until server reconciliation.
  5. Accepted project evidence may grant capped applied credit per contract §7.15; evidence alone does not confer mastery.
  6. Simulation and emulation supplement bench work; they do not satisfy applied requirements for tier L1.

Claims policy

Examples of permitted versus prohibited user-facing statements:

“Submit an attempt before hints unlock.”

“Report aided and unaided scores separately.”

Claims of neurostimulation, sleep optimization, or cognitive enhancement.

Unqualified “learn faster” or “top 1%” outcomes.

Medical or mental-health efficacy statements.
