Architecture overview

docs/03-architecture.md · architecture-index.md · Supplement: Architecture explainer

Summary

  • Client: Next.js PWA with service worker, IndexedDB outbox, and offline pack (later milestones).
  • Application tier: Next.js route handlers on Vercel; domain logic in shared TypeScript packages.
  • Data tier: Supabase (auth, PostgreSQL including the jobs queue, storage).
  • Worker tier: Python on Fly.io for symbolic grading and job handlers; optional sandbox for untrusted execution.
  • Learner state mutations occur only in TypeScript; the worker returns grading results (ADR-009).

Request lifecycle

  1. Client persists the attempt to a local outbox before network I/O.
  2. API validates JWT, payload, idempotency, and rate limits.
  3. Numeric and multiple-choice grades execute in-process with shared grading-core logic.
  4. Symbolic, code, and SPICE paths enqueue a jobs row and complete asynchronously.
  5. A single transaction updates attempt, review log, and skill state where applicable.

Job queue

PostgreSQL holds the queue; attempt and job rows commit together to prevent orphaned work. Workers claim rows with FOR UPDATE SKIP LOCKED. A future migration may replace the claim mechanism without changing handler contracts.
