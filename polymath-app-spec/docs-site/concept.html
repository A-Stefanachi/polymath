Plain-language product story · not the app itself

Practice that you can do without hints, then prove it on a real board.

Polymath is a phone-first practice app for one adult with about 8 hours a week. The purpose is to take you from near zero to working knowledge (L1) in each subject on the map. The first walk is math, electronics and embedded software; the rest of the subjects follow the same loop. Every task asks you to produce an answer. Progress is a working thing, not a streak.

  • Spaced retrieval
  • Graded feedback
  • Guided builds
  • No brain-hacking claims

The problem in four boxes

Most learning apps fail working adults in the same four ways.

⏱

Time is scarce

Working knowledge of one area is a long haul. Wasted minutes are expensive.

🎭

False progress

Tutorials and unguarded AI raise practice scores while unaided skill falls.

🌫

Forgetting

Without a schedule, skills fade. Without a graph, you hit material too early.

🔌

Hardware is physical

A quiz cannot tell you whether a board works on the bench.

One person, eight hours, two jobs

You are the only user for a long time. You also build the app. Those hours cannot be spent twice. Learning is reserved first.

A target week

About 7.5 hours of study in a good week. While building, reserve 2.5 of the 8 for learning; the rest is construction.

How one skill is learned

New skill: see it done, try with fading help, then recall it later the same day. After that the scheduler brings it back before it fades. Reviews use a fresh variant, so you remember the method, not the answer.

  1. Skill unlocks when prerequisites are solid
  2. Worked example
  3. Faded problem
  4. Same-day retrieval
  5. Later reviews with new numbers each time
  6. Looks mastered? If not, keep reviewing
  7. Needs a real applied attempt on the bench
  8. L1 · working knowledge

Micro · 5–20 min

Phone. Reviews and short problems. Starts in about a second when the app is warm.

Focus · 45–120 min

Laptop. Mixed task types. Code and longer problems live here.

Lab · 2–4 h

Bench. Parts list, safety card, then a build you can photograph or log.

The five rules that make the concept click

These are the v1.1 refinements. They do not add extra build work to the first slice. Tap a rule.

Progress is the next working thing

The home number is not “hours studied” or “nodes complete”. It is the next competence artifact: a named build plus the unaided checks still missing.

  1. L0 Blink an LED. Photo or note logged.
  2. Next Divider / RC filter. Scope trace matches the simulation.
  3. Then Transistor switch and regulator.
  4. L1 gate Skills in that area plus accepted project evidence.

Hour estimates are rough guesses. They are never the progress object.

Help is a ladder on this question, not a chatbot

Unguarded ChatGPT raised practice scores and cut unaided exam scores. A safe tutor mostly avoids harm. It is not the product.

You try first. Then you climb one rung at a time.

  1. 1 Nudge A pointer. No content of the answer.
  2. 2 Concept Which law or idea applies.
  3. 3 Step The next worked step only.
  4. 4 Reveal Full solution. This attempt no longer counts.
  1. Open question
  2. Tried something? If not, write what you tried
  3. Rung 1 → 2 → 3
  4. Rung 4 reveal · this attempt no longer counts
  5. Checkpoints: tutor hidden

Same skill, two places

Weekdays you can practise on a phone or laptop. Weekends you measure the same idea on a board. The review schedule is shared. A simulation never replaces the bench attempt required for working knowledge.

L1 still needs the bench attempt

We will not build our own circuit simulator. A later version may open someone else’s.

A build is proof of use, not a diploma

When evidence for a step is accepted, that skill gets applied credit. That is one of several mastery conditions. A working blink does not mark Ohm’s law mastered by itself.

  1. Finish a project step
  2. Evidence accepted? If not, credit stays pending
  3. L0 credit now
  4. Counts as the applied attempt only
  5. Still need unaided reviews on different days and variants
  6. Then the skill can be mastered · never L2 or L3 from a build

Working knowledge of each subject — first walk, then the rest

The purpose is L1 in each subject: you can complete a guided project in that area and debug it. That is not “top 1%” and not expert depth everywhere. It is working competence, subject by subject.

The first walk is math → electronics → embedded, proved by a working sensor-logging board. That is how we start, because one path lets the loop be tested. It is not a smaller ambition. After that path works, the same loop covers the other subjects on the map. One subject can later go deeper (L2).

What is proven, and what is a bet

Supported in other domains

  • Retrieval practice and spacing
  • Worked examples that fade
  • Mixing similar problem types after each is solid
  • Make the learner try before hints

Our combination is unproven

  • Skill graph + hardware builds + SPICE grading + tutor
  • So the app logs aided vs unaided scores from the start
  • We do not claim the app makes you faster until those scores say so

What we build first

Dates and hours are planning guesses, marked as such in the spec. The point of the picture is the order, not the calendar.

  1. Phase −1 · Anki + sheets · 4 weeks
  2. Lean slice · graph, reviews, numeric grading
  3. Go / no-go after 4 weeks of use
  4. Stop or cut → personal tool only
  5. Continue → tutor, sandbox, projects, beta, one group at a time

In the first slice

Sign-in, skill map, spaced reviews, worked example → retrieval, numeric grading, a progress page, a handwritten project log, a guided blink.

After a go decision

Tutor ladder, code and SPICE graders, evidence upload, unaided checkpoints, experiments, then maybe a small beta.

Not in the first slice

Pattern gym as an app feature, a built-in simulator, a study cohort, certificates, leaderboards, “learn everything”.
