Grading and tutor policy

docs/08-grading-and-tutor-spec.md, docs/12-security-privacy-compliance.md (LLM controls)

Summary

  • Deterministic graders evaluate numeric, symbolic, test, and simulation outputs before any model-based judgment.
  • Large language models support rubrics, tagging, drafting, and gated tutoring — not sole pass/fail for executable tasks.
  • Learner code executes only in the sandbox service.
  • Hint levels 0–4 apply; level 4 discloses the reference solution and ends credit for the attempt.

TypeScript grading-core in the API tier (and client offline for cached items). Unit tolerance and dimensional analysis. Target p95 latency under two seconds.

Worker SymPy equivalence with a hard timeout (~1.5 s). Long-running work falls back to the job queue.

Job handler invokes sandbox runners (compile/test, ngspice, kicad-cli). Output compared to verified reference; network disabled.

Policy gate requires an attempt before model invocation. Prompt includes item, learner response, and reference; leak filter blocks final answers below level 4. Checkpoints disable the tutor.

Item verification gate

  1. Author commits template YAML; CI runs lint and generation checks.
  2. Independent verification recomputes answers for multiple seeds.
  3. Database status must be verified before serve eligibility.
  4. Confirmed defects trigger retirement within 48 hours (SM-07).
A large language model must not be the only authority for numeric correctness or automated test pass/fail.
