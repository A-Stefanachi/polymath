Learner model and scheduling

docs/02-learning-science-spec.md, docs/06-learner-model-and-scheduler-spec.md (canonical for FSRS and mastery)

Summary

  • Each skill maintains an independent FSRS schedule for spaced retrieval.
  • The frontier selects new material that satisfies prerequisite and tier constraints.
  • The session builder assembles tasks to fit the learner’s chosen duration and device context.
  • Mastery requires verified attempts, template diversity, temporal spread, and applied rules where applicable.

Session types

Micro

Up to 20 minutes; optimized for phone context and retrieval density.

Focus

45–120 minutes; desktop-oriented problem sets and assessments.

Lab

120–240 minutes; bench context and project steps.

Windows of 21–44 minutes are scheduled as a single micro session (optionally chained). Project steps must not use that duration band.

Instructional sequence per skill

  1. Worked example — full reference solution presented once.
  2. Faded problems — progressive reduction of scaffolding.
  3. Same-day retrieval — novel verified variant without hints.
  4. FSRS reviews — additional seeds over weeks.
  5. Checkpoints (deferred in lean slice) — strict-unaided assessment.
  6. Project steps — predict, build, measure, submit evidence.

Mastery definition (overview)

The scheduler promotes a skill to mastered when contract and doc 06 conditions are met: verified attempts across distinct templates, minimum calendar span where required, FSRS ratings, and for applied skills the needs_applied bench gap rule. Skills may transition to decayed when estimated retrievability falls below threshold without erasing tier attainment.

Evidence basis

Supported mechanisms [R/V]

  • Retrieval practice
  • Spaced scheduling
  • Faded worked examples
  • Attempt-first tutoring

Product hypotheses [P]

  • Integrated skill graph with hardware projects
  • SPICE and unit-test execution grading at scale
  • Cross-domain interleaving policy
Tutor dependence (SM-04): monitor the gap between aided practice and strict-unaided checkpoints; policy tightens when the gap exceeds defined thresholds.
