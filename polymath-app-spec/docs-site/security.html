Security and privacy

docs/12-security-privacy-compliance.md

Summary

  • Client input, uploads, and submitted code are treated as untrusted.
  • The sandbox runtime holds no database credentials, model API keys, or network egress.
  • LLM requests include item and response text only — not account identifiers.
  • Analytics use the internal events table; third-party trackers are out of scope for v1.
  • Data export and deletion flows are specified before beta (M4).

Primary threats and controls

  • Malicious learner code — confined to sandbox with CPU, memory, and wall-clock limits.
  • Compromised session token — row-level security limits data exposure; privileged keys remain server-side.
  • Prompt injection via item content — tutor policy, leak filtering, versioned prompt templates.
  • Evidence uploads — type and size limits, signed URLs, server-side validation.

LLM usage controls

  1. Centralized LlmClient in TypeScript and Python implementations.
  2. Per-user and global daily spend caps.
  3. Attempt-first gating reduces unnecessary invocations.
  4. Structured outputs validated with a single repair retry.

Compliance note

Legal review is required for GDPR-style rights, research consent, and retention statements marked for counsel in doc 12. Treat those sections as draft until formally approved.
