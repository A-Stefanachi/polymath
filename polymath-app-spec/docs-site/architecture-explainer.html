Four boxes, one database, no extra queue.

One person builds this with AI agents, about 8 hours a week. So the architecture stays boring: a phone app, a web server, Postgres, and later a worker with a locked-down sandbox. Learner code never runs next to secrets. An LLM never grades a number or a test suite by itself.

  • PWA, not native apps
  • Next.js UI + API together
  • Supabase Auth + Postgres + files
  • Fly worker + sandbox later

The constraints that pick the stack

One builder

Few moving parts. No Kubernetes. The job list lives in Postgres, the database we already have.

Phone first

Installable PWA. A 15-minute session must start from cache and work on a train.

Untrusted code

Learner C, Python and SPICE netlists run in a jail with no keys and no internet.

Honest cost

Founder-funded. LLM spend is capped. Lean hosting is tens of dollars a month, not hundreds.

The system as four boxes

People sit outside. GitHub ships content and deploys. Claude is called only with the question and the answer, never a name or email.

Phone / laptop

Next.js PWA

Screens, service worker, IndexedDB. Answers are saved on the device before they go online, so a dropped signal cannot lose work.

  • Today, session, map, progress, later projects and tutor
  • Local numeric / multiple-choice check while offline
  • Talks HTTPS to the API
Vercel

UI + API in one app

Route handlers are thin: check login, validate, call a package, return JSON. The brains live in TypeScript packages: scheduler, numeric grader, tutor policy.

  • Magic-link session from Supabase
  • Only this process writes learner state (mastery, reviews)
  • Privileged database key never reaches the browser
Supabase

Auth, Postgres, file store

System of record. Every table has row-level security. The jobs table is the queue. Photos and exports sit in private buckets.

  • Email magic link, no password
  • No public write API for learning data
  • Lean slice: founder lives on staging until there is a second user
Fly.io · later

Worker, then sandbox

Python claims jobs: algebra, code tests, SPICE, evidence checks. The sandbox is a second machine with no secrets. The worker never executes learner code itself.

  • Worker can talk to Claude for rubrics, not for Ohm’s law
  • Sandbox: nsjail inside a small VM, no network
  • Results come back; TypeScript still updates mastery

What happens when you submit an answer

Fast things stay in the web app. Slow or dangerous things become a job. Tap a path.

A number with units — under 2 seconds

  1. Phone writes the attempt to a local outbox first
  2. API loads the verified answer key (not visible to the learner)
  3. Same TypeScript grader as the phone: value, units, tolerance
  4. One database transaction: attempt, review log, skill update
  5. Phone deletes the outbox row

No worker. No LLM. 26.4 cents and $0.264 are the same answer.

An algebraic form — worker, still quick

  1. API asks the worker: are these two expressions the same?
  2. SymPy runs with a 1.5 s kill switch
  3. If the worker is slow, the attempt is stored as pending and a job finishes it
  4. Mastery still updates only in TypeScript

Code or a netlist — job + jail

  1. API stores the attempt and enqueues a job in the same commit
  2. Worker claims the job
  3. Sandbox compiles and runs tests, or ngspice, with CPU / memory / time caps and no network
  4. Worker compares output to the verified reference
  5. Worker calls the API; TypeScript applies the review

Target: done within 20 seconds for most runs. KiCad checks can take longer and only appear for the last board.

A hint — after you have tried

  1. Policy code checks: is there an attempt? Which rung is allowed?
  2. If the gate is shut, a canned line. No model call.
  3. Otherwise Claude sees the item, your attempt, and the reference solution. No email, no name.
  4. A filter blocks a leaked final answer below rung 4
  5. Checkpoints have no tutor button at all

Questions are data in git, not typed into the app

A learner is never served an unverified item. Humans review templates. Machines stamp each generated variant.

  1. YAML in git: skills, edges, problem templates, projects
  2. Lint: schema, no cycles, licence and source present
  3. Verify: generate several seeds, recompute the answer independently
  4. Sync into Postgres by key
  5. Only verified items can appear in a session

One repo, sharp walls

TypeScript packages have no database and no network. The sandbox image shares no code and no environment with the worker.

  • apps/web screens and thin API routes
    • src/app · pages
    • src/server/privileged · the only place with the service-role key
  • packages/ pure logic, easy to test
    • scheduler · what to practise next
    • grading-core · numbers and choices
    • tutor-policy · attempt-first, leak filter
    • llm · one client, fake in tests
  • services/ later, on Fly
    • worker · jobs, SymPy, talks to sandbox
    • sandbox-runner · jail, no secrets
  • content/ · prompts/ · supabase/ curriculum, tutor text, migrations

Rules CI will fail on

  • UI components cannot import the privileged database client.
  • Packages cannot open a socket or read process.env.
  • Only packages/llm calls the LLM provider.
  • The Python worker cannot write skill_state or the review log.

Build order matches the lean slice

You do not stand up Fly on day one. The first months are the phone, the database, and numeric grading — enough to study every day.

First (lean slice)

  • Repo, CI, claims lint, secrets scan
  • Supabase schema + RLS tests
  • Magic link, session builder, FSRS
  • Numeric / choice / later symbolic grading
  • Progress page, PWA shell, manual project log

After a go decision

  • Worker and sandbox (code, SPICE)
  • Tutor ladder
  • Evidence upload and review
  • Checkpoints, experiments, privacy export
  • Production project, then maybe a beta

Monthly money, planning guess: about $15–35 while it is just you; about $45–65 if Vercel Pro is required. A small beta is more like $190–260. Recheck vendor pages before you rely on a number.

Decisions in one line each

PWA, not stores

One codebase. Native apps are two reviews and two toolchains.

UI and API together

A second backend would duplicate auth and the scheduler.

Supabase

Auth, Postgres and files in one project you can actually run alone.

Jobs in Postgres

The attempt and its job commit together. No lost work, no extra service.

Sandbox is mute

No database URL, no LLM key, no network. Two isolation layers.

Learner state is TypeScript

One place for FSRS and mastery. The worker only returns a grade.
